# デプロイ運用ガイド - Docker Compose 完全デプロイ

## 📋 概要

本ドキュメントでは、`docker-compose.full.dev.yml` 設定ファイルを使用して、完全な langchainChatBot システム（ARS システムと Chatbot システムの統合デプロイ）をデプロイする方法を詳しく説明します。

## 🚀 クイックスタート

### 前提条件

#### 必須ソフトウェア

- **Docker**: 20.10+
- **Docker Compose**: 2.0+
- **Git**: コードクローン用
- **最低 8GB RAM**: 推奨 16GB
- **最低 20GB ディスク容量**: イメージとデータ用

#### オプションソフトウェア

- **Ollama**: ローカル LLM と Embedding 用（他のマシンで実行可能）

### ステップ 1: プロジェクトのクローン

```bash
# プロジェクトをローカルにクローン
cd /path/to/your/workspace
git clone <repository-url> aiportal.chatbot
cd aiportal.chatbot
```

### ステップ 2: 設定ファイルの確認

`docker-compose.full.dev.yml` 設定を確認：

```bash
# Windows
type docker-compose.full.dev.yml

# Linux/Mac
cat docker-compose.full.dev.yml
```

### ステップ 3: 環境変数の設定

#### Ollama アドレスの変更（使用する場合）

`docker-compose.full.dev.yml` を編集し、以下の設定を Ollama サーバーのアドレスに変更：

```yaml
environment:
  - OPENAI_API_BASE=http://192.168.1.101:11434/v1  # あなたのアドレスに変更
  - EMBEDDING_BASE_URL=http://192.168.1.101:11434  # あなたのアドレスに変更
```

#### LLM 設定の変更（オプション）

```yaml
environment:
  - LLM_PROVIDER=カスタム              # openai, anthropic, gemini, カスタム
  - OPENAI_MODEL_NAME=qwen2.5:7b      # モデル名
  - OPENAI_TEMPERATURE=0.7            # Temperature パラメータ
  - EMBEDDING_MODEL_NAME=nomic-embed-text  # Embedding モデル
```

### ステップ 4: サービスの起動

#### 完全起動（推奨）

```bash
# すべてのサービスをビルドして起動
docker compose -f docker-compose.full.dev.yml up -d --build

# ログを確認
docker compose -f docker-compose.full.dev.yml logs -f

# 特定のサービスのログを確認
docker compose -f docker-compose.full.dev.yml logs -f chatbot-backend
```

#### 段階的起動（デバッグ用）

```bash
# 1. まずデータベースを起動
docker compose -f docker-compose.full.dev.yml up -d ars-mysql-db chatbot-qdrant

# 2. データベースの準備完了を待つ（約 60 秒）
docker compose -f docker-compose.full.dev.yml logs -f ars-mysql-db

# 3. バックエンドサービスを起動
docker compose -f docker-compose.full.dev.yml up -d ars-backend chatbot-backend

# 4. フロントエンドサービスを起動
docker compose -f docker-compose.full.dev.yml up -d ars-frontend chatbot-frontend
```

## 📝 サービス詳細設定

### MySQL データベース設定

```yaml
ars-mysql-db:
  image: mysql:8.0
  container_name: mysql-db
  environment:
    MYSQL_ROOT_PASSWORD: root          # Root パスワード
    MYSQL_DATABASE: ars_db             # デフォルトデータベース
    TZ: Asia/Tokyo                     # タイムゾーン設定
    MYSQL_CHARSET: utf8mb4             # 文字セット
    MYSQL_COLLATION: utf8mb4_general_ci
  ports:
    - "3306:3306"
  volumes:
    - ./ars-backend/ZScript/Db/Mysql-Dev:/var/lib/mysql:cached
    - ./ars-backend/ZScript/Db/MySQLConfig:/etc/mysql/conf.d:ro
    - ./ars-backend/ZScript/Sql/Mysql:/docker-entrypoint-initdb.d:ro
  healthcheck:
    test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-proot"]
    interval: 10s
    timeout: 5s
    start_period: 60s
    retries: 5
```

**主要設定の説明**：

- `healthcheck`: データベースが完全に起動してから依存サービスを起動
- `start_period: 60s`: MySQL に 60 秒の起動時間を与える
- `volumes`: データをローカルディレクトリに永続化

### Qdrant ベクトルデータベース設定

```yaml
chatbot-qdrant:
  image: qdrant/qdrant:latest
  container_name: chatbot-qdrant
  ports:
    - "6333:6333"  # HTTP API
    - "6334:6334"  # gRPC API
  volumes:
    - chatbot_qdrant_data:/qdrant/storage
  environment:
    - TZ=Asia/Tokyo
    - QDRANT__SERVICE__HTTP_PORT=6333
    - QDRANT__SERVICE__GRPC_PORT=6334
```

**主要設定の説明**：

- `chatbot_qdrant_data`: 名前付きボリューム、データ永続化
- ポート 6333: Web UI と HTTP API
- ポート 6334: gRPC 高性能インターフェース

### Chatbot Backend 設定

```yaml
chatbot-backend:
  build: ./langchainChatBot/backend
  image: itccloudsoft/chatbot-backend:dev
  container_name: chatbot-backend
  depends_on:
    ars-mysql-db:
      condition: service_healthy
    chatbot-qdrant:
      condition: service_started
  environment:
    # データベース設定
    - MYSQL_HOST=ars-mysql-db
    - MYSQL_PORT=3306
    - MYSQL_USER=root
    - MYSQL_PASSWORD=root
    - MYSQL_DATABASE=chatbot
    
    # Qdrant 設定
    - QDRANT_HOST=qdrant
    - QDRANT_PORT=6333
    
    # CORS 設定
    - CORS_ORIGINS=http://localhost:3001
    
    # 認証設定
    - SUPER_ADMIN_PASSWORD=admin123
    - ACCESS_TOKEN_EXPIRE_MINUTES=60
    - REFRESH_TOKEN_EXPIRE_DAYS=30
    
    # LLM 設定
    - LLM_PROVIDER=カスタム
    - OPENAI_API_BASE=http://192.168.1.101:11434/v1
    - OPENAI_API_KEY=ollama
    - OPENAI_MODEL_NAME=qwen2.5:7b
    - OPENAI_TEMPERATURE=0.7
    - OPENAI_MAX_TOKENS=2048
    
    # Embedding 設定
    - EMBEDDING_PROVIDER=ollama
    - EMBEDDING_BASE_URL=http://192.168.1.101:11434
    - EMBEDDING_MODEL_NAME=nomic-embed-text
    
    # タイムアウト設定
    - LLM_TEST_TIMEOUT=120
  ports:
    - "8000:8000"
```

**主要設定の説明**：

- `depends_on`: データベースが健全な状態になってから起動
- `MYSQL_HOST=ars-mysql-db`: コンテナ名をホスト名として使用
- `QDRANT_HOST=qdrant`: コンテナホスト名を使用
- `LLM_TEST_TIMEOUT=120`: LLM テストタイムアウト時間（秒）

### Chatbot Frontend 設定

```yaml
chatbot-frontend:
  build: ./langchainChatBot/frontend
  image: itccloudsoft/chatbot-frontend:dev
  container_name: chatbot-frontend
  depends_on:
    chatbot-backend:
      condition: service_started
  environment:
    - TZ=Asia/Tokyo
    - VITE_TEST_TIMEOUT=120000  # テストタイムアウト（ミリ秒）
  ports:
    - "3001:80"
```

**主要設定の説明**：

- ポートマッピング: `3001:80` - コンテナ内の Nginx は 80 をリッスン、外部は 3001 でアクセス
- ビルド時に `VITE_API_URL` が `http://localhost:8000` に設定される

## 🐛 トラブルシューティング

### 問題 1: MySQL 起動失敗

**症状**：

```
ars-mysql-db | [ERROR] [MY-000067] [Server] unknown variable 'default-authentication-plugin=mysql_native_password'
```

**解決方法**：

1. MySQL 設定ファイルを確認
2. MySQL 8.0 互換性を確認
3. 古いデータボリュームを削除して再初期化：

```bash
docker compose -f docker-compose.full.dev.yml down -v
docker compose -f docker-compose.full.dev.yml up -d
```

### 問題 2: Chatbot Backend がデータベースに接続できない

**症状**：

```
chatbot-backend | ERROR: Can't connect to MySQL server on 'ars-mysql-db'
```

**解決方法**：

1. MySQL ヘルス状態を確認：

```bash
docker compose -f docker-compose.full.dev.yml ps ars-mysql-db
```

2. ネットワーク接続を確認：

```bash
docker compose -f docker-compose.full.dev.yml exec chatbot-backend ping ars-mysql-db
```

3. データベースが作成されているか確認：

```bash
docker compose -f docker-compose.full.dev.yml exec ars-mysql-db mysql -u root -proot -e "SHOW DATABASES;"
```

### 問題 3: Qdrant 接続失敗

**症状**：

```
chatbot-backend | ERROR: Cannot connect to Qdrant at qdrant:6333
```

**解決方法**：

1. Qdrant ステータスを確認：

```bash
docker compose -f docker-compose.full.dev.yml ps chatbot-qdrant
```

2. Qdrant Dashboard にアクセス：

```
http://localhost:6333/dashboard
```

3. ネットワーク接続を確認：

```bash
docker compose -f docker-compose.full.dev.yml exec chatbot-backend curl http://qdrant:6333/
```

### 問題 4: フロントエンドがバックエンド API にアクセスできない

**症状**：

- フロントエンドにネットワークエラーが表示される
- CORS エラー

**解決方法**：

1. バックエンド CORS 設定を確認：

```yaml
environment:
  - CORS_ORIGINS=http://localhost:3001
```

2. バックエンドが正常に動作していることを確認：

```bash
curl http://localhost:8000/health
```

3. ブラウザコンソールのネットワークリクエストを確認

### 問題 5: Ollama 接続タイムアウト

**症状**：

```
chatbot-backend | ERROR: Timeout connecting to Ollama at http://192.168.1.101:11434
```

**解決方法**：

1. Ollama サーバーにアクセスできることを確認：

```bash
curl http://192.168.1.101:11434/api/tags
```

2. タイムアウト時間を増やす：

```yaml
environment:
  - LLM_TEST_TIMEOUT=180  # 3 分に増やす
```

3. ファイアウォール設定を確認

4. ローカル Ollama を使用（docker-compose.yml の ollama サービスのコメントを解除）

### 問題 6: コンテナメモリ不足

**症状**：

```
chatbot-backend | Killed
```

**解決方法**：

1. Docker メモリ制限を増やす（Docker Desktop 設定）

2. docker-compose.yml にメモリ制限を追加：

```yaml
deploy:
  resources:
    limits:
      memory: 2G
    reservations:
      memory: 1G
```

3. メモリ使用状況を監視：

```bash
docker stats
```

## 📦 データバックアップと復元

### 完全バックアップスクリプト

`backup.sh` を作成：

```bash
#!/bin/bash
BACKUP_DIR="./backups/$(date +%Y%m%d_%H%M%S)"
mkdir -p $BACKUP_DIR

# MySQL をバックアップ
docker compose -f docker-compose.full.dev.yml exec -T ars-mysql-db mysqldump -u root -proot --all-databases > $BACKUP_DIR/mysql_all.sql

# Qdrant をバックアップ
docker run --rm -v chatbot_qdrant_data:/data -v $(pwd)/$BACKUP_DIR:/backup alpine tar czf /backup/qdrant.tar.gz -C /data .

echo "バックアップ完了: $BACKUP_DIR"
```

### 自動バックアップ（Cron）

```bash
# crontab に追加
0 2 * * * /path/to/backup.sh
```
