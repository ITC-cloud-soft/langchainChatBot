# langchainChatBot プロジェクト概要

## 📋 プロジェクト紹介

langchainChatBot は、**FastAPI** と **React** をベースとしたエンタープライズグレードのインテリジェントチャットボットシステムです。LangChain、Qdrant ベクトルデータベース、MySQL リレーショナルデータベースを統合し、完全な RAG（検索拡張生成）機能を提供します。

### コア機能

- 🏢 **シングルテナント設計** - 単一組織向けに設計され、シンプルで保守しやすいアーキテクチャ
- 💬 **リアルタイムストリーミング対話** - ストリーミングレスポンスをサポートし、スムーズなユーザー体験を提供
- 🤖 **柔軟な LLM 統合** - OpenAI、Anthropic、Google Gemini、カスタム API をサポート
- 📚 **ナレッジベース管理** - 複数のドキュメント形式をサポート、ベクトル検索ベースのインテリジェント Q&A
- 👥 **ユーザー権限管理** - ロールベースアクセス制御（RBAC）
- 🔐 **JWT 認証** - セキュアな Token 認証メカニズム、自動リフレッシュをサポート
- ⚙️ **ホットリロード設定** - config.toml 設定ファイルの変更が即座に反映

## 🔑 コア機能モジュール

### 1. 認証・認可モジュール

- **JWT Token 認証**
  - Access Token（30分有効期限）
  - Refresh Token（7日有効期限）
  - 自動 Token リフレッシュメカニズム
  
- **ロール権限管理**
  - Admin: 完全アクセス権限（ユーザー管理、システム設定、ナレッジベース管理）
  - User: 基本チャット機能

- **パスワードセキュリティ**
  - bcrypt 暗号化保存
  - パスワード強度検証

### 2. チャット対話モジュール

- **リアルタイムストリーミングレスポンス**
  - Server-Sent Events (SSE) 実装
  - 文字単位のストリーミング出力
  - 中断と再試行をサポート

- **セッション管理**
  - マルチセッションサポート
  - セッション履歴の永続化
  - セッション検索とフィルタリング

- **コンテキスト管理**
  - 対話履歴メモリ（最大履歴数設定可能）
  - コンテキストキャッシュ最適化
  - インテリジェントなコンテキスト切り詰め

### 3. RAG ナレッジベースモジュール

- **ドキュメント処理**
  - サポート形式: PDF, TXT, DOCX, MD
  - ドキュメントチャンキング
  - メタデータ抽出

- **ベクトル検索**
  - Qdrant ベクトルデータベース
  - 意味的類似度検索
  - ハイブリッド検索戦略

- **Embedding 生成**
  - Ollama ローカルモデル
  - OpenAI Embedding API
  - 設定可能な次元数（デフォルト 768）

### 4. LLM 設定モジュール

- **マルチプロバイダーサポート**
  - OpenAI (GPT-3.5, GPT-4)
  - Anthropic (Claude)
  - Google (Gemini)
  - カスタム API（OpenAI 形式互換）

- **パラメータチューニング**
  - Temperature（創造性制御）
  - Max Tokens（出力長）
  - Top P（核サンプリング）
  - Frequency/Presence Penalty（繰り返し制御）

- **設定管理**
  - ホットリロード設定
  - 設定インポート/エクスポート
  - 接続テスト機能

### 5. ユーザー管理モジュール

- **ユーザー CRUD**
  - 作成、読み取り、更新、削除
  - バッチ操作サポート
  - ユーザー検索とフィルタリング

- **権限制御**
  - ロール割り当て
  - アカウント有効化/無効化
  - パスワードリセット

### 6. ARS Flow 連携モジュール

- **Flow 識別と実行**
  - LLM の ReAct 出力から Flow ID を自動識別
  - Flow 名称直接マッチング（LLM 非 JSON 応答時のフォールバック）
  - ARS `/execute` API 経由で SSFlow ワークフローを起動

- **動的申請フォーム（ARSFlowForm）**
  - ARS から取得したパラメータ定義に基づき MUI フォームを動的生成
  - 社員情報（氏名・会社名・所属・コード）を ARS Flow 11 経由で自動入力
  - `MainTblName_value` の JSON 組み立て・送信
  - フォームバリデーション（必須・数字のみチェック）
  - 申請内容グループを MUI Accordion（折りたたみ）で表示
  - 送信済みフォームは読み取り専用で表示・入力値保持

- **実行結果表示（FlowResultDisplay）**
  - 各 Tool のステップ別実行結果を表示
  - フロー名称を優先表示（Flow ID フォールバック）

- **ARS Token 管理**
  - `ArsService.get_required_ars_token()` による共通化
  - 未設定時は HTTP 503 を返してユーザーに通知

### 7. SSFlow 連携・ユーザー同期モジュール

- **内部 API（認証不要）**
  - `POST /api/internal/users`：SSFlow からのユーザー upsert
  - email 重複時も 200 を返すべき（安全な upsert）

- **管理者画面のユーザー編集**
  - `PUT /api/auth/users/{user_id}` で role / email 変更
  - フロントエンドのユーザー一覧に編集ボタン・モーダルを追加

- **社員情報取得**
  - `GET /api/users/employee-info` が ARS Flow 11 を経由して SSFlow から社員情報を取得
  - `EMPLOYEE_INFO_API_URL` 環境変数を廃止し ARS 経由に統一

### 8. 通知システム（Novu + SSFlow 承認）

- **リアルタイム通知**
  - Novu WebSocket による未読通知のリアルタイム更新
  - 通知ベル（NotificationBell）にてドロワー表示・申請番号表示

- **承認フォームダイアログ（ApprovalFormDialog）**
  - 承認/否認ボタン + コメント入力
  - 事前チェック: SSFlow API で WFState を確認し処理済みの場合は 3 パターンのメッセージを表示
    - WFState=3 + completed: 最終承認者名・フロー完了
    - WFState=4 + denied: 否認者名
    - WFState=1 + 別担当者処理済: 承認者名・現在ノード名

- **申請実行**
  - ARS Flow 10 経由で SSFlow 申請を作成
  - ARS Flow 8 経由で SSFlow 承認/否認を実行

## 🔄 データフロー

### チャット対話フロー

```
1. ユーザーがメッセージを入力
   ↓
2. Frontend が POST /api/chat/stream を送信
   ↓
3. Backend ChatService が処理
   ↓
4. 関連ナレッジを検索（Qdrant ベクトル検索）
   ↓
5. プロンプトテンプレートを構築
   ↓
6. LLM API を呼び出し（ストリーミングレスポンス）
   ↓
7. リアルタイムで Token ストリームを返す
   ↓
8. 対話履歴を保存（MySQL）
   ↓
9. Frontend がメッセージをレンダリング
```

### ナレッジベースアップロードフロー

```
1. ユーザーがドキュメントをアップロード
   ↓
2. Frontend が POST /api/knowledge/documents/upload を送信
   ↓
3. Backend がファイルをローカルに保存
   ↓
4. ドキュメント解析（PDF/DOCX/TXT/MD）
   ↓
5. テキストチャンキング
   ↓
6. Embedding ベクトルを生成
   ↓
7. Qdrant に保存
   ↓
8. アップロード結果を返す
```

## 📈 パフォーマンス最適化

### バックエンド最適化

- 非同期 I/O（async/await）
- データベースコネクションプール（20 接続）
- ベクトル検索キャッシュ

- チャット履歴の遅延ロード（初期 15 件、上スクロールで過去 10 件追加取得）
- コンポーネント遅延ロード
- Memo による再レンダリング最適化
- Debounce 入力処理

- ワンクリックですべてのサービスを起動
- サービス依存関係管理
- データ永続化ボリューム
- ヘルスチェック設定

### 本番環境推奨事項

- Nginx リバースプロキシの使用
- HTTPS 有効化（Let's Encrypt）
- ログ収集設定（ELK）
- モニタリングアラート実装（Prometheus + Grafana）
- データベース定期バックアップ
- CI/CD パイプライン実装

## 📝 設定説明

### 主要設定項目

**config.toml**

```toml
[llm]
provider = "カスタム"           # LLM プロバイダー
api_base = "http://..."         # API エンドポイント
api_key = "your-key"            # API キー
model_name = "qwen2.5:7b"       # モデル名
temperature = 0.7               # Temperature パラメータ

[embedding]
provider = "ollama"             # Embedding プロバイダー
base_url = "http://..."         # Ollama アドレス
model_name = "nomic-embed-text" # Embedding モデル
dimension = 768                 # ベクトル次元数

[database]
host = "localhost"              # MySQL ホスト
port = 3306                     # MySQL ポート
username = "root"               # データベースユーザー
password = "root"               # データベースパスワード
database = "chatbot"            # データベース名
```

**.env**

```bash
JWT_SECRET_KEY=your-secret-key
JWT_ALGORITHM=HS256
JWT_ACCESS_TOKEN_EXPIRE_MINUTES=30
JWT_REFRESH_TOKEN_EXPIRE_DAYS=7
SUPER_ADMIN_PASSWORD=admin123
```
