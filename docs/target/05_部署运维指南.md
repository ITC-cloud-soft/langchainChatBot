# 部署运维指南 - Docker Compose 完整部署

## 📋 概述

本文档详细说明如何使用 `docker-compose.full.dev.yml` 配置文件部署完整的 langchainChatBot 系统，包括 ARS 系统和 Chatbot 系统的集成部署。

## 🚀 快速开始

### 前置要求

#### 必需软件
- **Docker**: 20.10+ 
- **Docker Compose**: 2.0+
- **Git**: 用于克隆代码
- **至少 8GB RAM**: 推荐 16GB
- **至少 20GB 磁盘空间**: 用于镜像和数据

#### 可选软件
- **Ollama**: 用于本地 LLM 和 Embedding（可在其他机器上运行）

### 步骤 1: 克隆项目

```bash
# 克隆项目到本地
cd /path/to/your/workspace
git clone <repository-url> aiportal.chatbot
cd aiportal.chatbot
```

### 步骤 2: 检查配置文件

查看 `docker-compose.full.dev.yml` 配置：

```bash
# Windows
type docker-compose.full.dev.yml

# Linux/Mac
cat docker-compose.full.dev.yml
```

### 步骤 3: 配置环境变量

#### 修改 Ollama 地址（如果使用）

编辑 `docker-compose.full.dev.yml`，找到以下配置并修改为你的 Ollama 服务器地址：

```yaml
environment:
  - OPENAI_API_BASE=http://192.168.1.101:11434/v1  # 修改为你的地址
  - EMBEDDING_BASE_URL=http://192.168.1.101:11434  # 修改为你的地址
```

#### 修改 LLM 配置（可选）

```yaml
environment:
  - LLM_PROVIDER=カスタム              # openai, anthropic, gemini, カスタム
  - OPENAI_MODEL_NAME=qwen2.5:7b      # 模型名称
  - OPENAI_TEMPERATURE=0.7            # 温度参数
  - EMBEDDING_MODEL_NAME=nomic-embed-text  # Embedding 模型
```

### 步骤 4: 启动服务

#### 完整启动（推荐）

```bash
# 构建并启动所有服务
docker compose -f docker-compose.full.dev.yml up -d --build

# 查看日志
docker compose -f docker-compose.full.dev.yml logs -f

# 查看特定服务日志
docker compose -f docker-compose.full.dev.yml logs -f chatbot-backend
```

#### 分步启动（调试用）

```bash
# 1. 先启动数据库
docker compose -f docker-compose.full.dev.yml up -d ars-mysql-db chatbot-qdrant

# 2. 等待数据库就绪（约 60 秒）
docker compose -f docker-compose.full.dev.yml logs -f ars-mysql-db

# 3. 启动后端服务
docker compose -f docker-compose.full.dev.yml up -d ars-backend chatbot-backend

# 4. 启动前端服务
docker compose -f docker-compose.full.dev.yml up -d ars-frontend chatbot-frontend
```

### 步骤 5: 验证部署

## 📝 服务详细配置

### MySQL 数据库配置

```yaml
ars-mysql-db:
  image: mysql:8.0
  container_name: mysql-db
  environment:
    MYSQL_ROOT_PASSWORD: root          # Root 密码
    MYSQL_DATABASE: ars_db             # 默认数据库
    TZ: Asia/Tokyo                     # 时区设置
    MYSQL_CHARSET: utf8mb4             # 字符集
    MYSQL_COLLATION: utf8mb4_general_ci
  ports:
    - "3306:3306"
  volumes:
    - ./ars-backend/ZScript/Db/Mysql-Dev:/var/lib/mysql:cached
    - ./ars-backend/ZScript/Db/MySQLConfig:/etc/mysql/conf.d:ro
    - ./ars-backend/ZScript/Sql/Mysql:/docker-entrypoint-initdb.d:ro
  healthcheck:
    test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-proot"]
    interval: 10s
    timeout: 5s
    start_period: 60s
    retries: 5
```

**关键配置说明**：
- `healthcheck`: 确保数据库完全启动后才启动依赖服务
- `start_period: 60s`: 给予 MySQL 60 秒的启动时间
- `volumes`: 数据持久化到本地目录

### Qdrant 向量数据库配置

```yaml
chatbot-qdrant:
  image: qdrant/qdrant:latest
  container_name: chatbot-qdrant
  ports:
    - "6333:6333"  # HTTP API
    - "6334:6334"  # gRPC API
  volumes:
    - chatbot_qdrant_data:/qdrant/storage
  environment:
    - TZ=Asia/Tokyo
    - QDRANT__SERVICE__HTTP_PORT=6333
    - QDRANT__SERVICE__GRPC_PORT=6334
```

**关键配置说明**：
- `chatbot_qdrant_data`: 命名卷，数据持久化
- 端口 6333: Web UI 和 HTTP API
- 端口 6334: gRPC 高性能接口

### Chatbot Backend 配置

```yaml
chatbot-backend:
  build: ./langchainChatBot/backend
  image: itccloudsoft/chatbot-backend:dev
  container_name: chatbot-backend
  depends_on:
    ars-mysql-db:
      condition: service_healthy
    chatbot-qdrant:
      condition: service_started
  environment:
    # 数据库配置
    - MYSQL_HOST=ars-mysql-db
    - MYSQL_PORT=3306
    - MYSQL_USER=root
    - MYSQL_PASSWORD=root
    - MYSQL_DATABASE=chatbot
    
    # Qdrant 配置
    - QDRANT_HOST=qdrant
    - QDRANT_PORT=6333
    
    # CORS 配置
    - CORS_ORIGINS=http://localhost:3001
    
    # 认证配置
    - SUPER_ADMIN_PASSWORD=admin123
    - ACCESS_TOKEN_EXPIRE_MINUTES=60
    - REFRESH_TOKEN_EXPIRE_DAYS=30
    
    # LLM 配置
    - LLM_PROVIDER=カスタム
    - OPENAI_API_BASE=http://192.168.1.101:11434/v1
    - OPENAI_API_KEY=ollama
    - OPENAI_MODEL_NAME=qwen2.5:7b
    - OPENAI_TEMPERATURE=0.7
    - OPENAI_MAX_TOKENS=2048
    
    # Embedding 配置
    - EMBEDDING_PROVIDER=ollama
    - EMBEDDING_BASE_URL=http://192.168.1.101:11434
    - EMBEDDING_MODEL_NAME=nomic-embed-text
    
    # 超时配置
    - LLM_TEST_TIMEOUT=120
  ports:
    - "8000:8000"
```

**关键配置说明**：
- `depends_on`: 确保数据库健康后才启动
- `MYSQL_HOST=ars-mysql-db`: 使用容器名称作为主机名
- `QDRANT_HOST=qdrant`: 使用容器 hostname
- `LLM_TEST_TIMEOUT=120`: LLM 测试超时时间（秒）

### Chatbot Frontend 配置

```yaml
chatbot-frontend:
  build: ./langchainChatBot/frontend
  image: itccloudsoft/chatbot-frontend:dev
  container_name: chatbot-frontend
  depends_on:
    chatbot-backend:
      condition: service_started
  environment:
    - TZ=Asia/Tokyo
    - VITE_TEST_TIMEOUT=120000  # 测试超时（毫秒）
  ports:
    - "3001:80"
```

**关键配置说明**：
- 端口映射: `3001:80` - 容器内 Nginx 监听 80，外部访问 3001
- 构建时会将 `VITE_API_URL` 设置为 `http://localhost:8000`

## 🔧 常用运维命令

### 服务管理

```bash
# 启动所有服务
docker compose -f docker-compose.full.dev.yml up -d

# 停止所有服务
docker compose -f docker-compose.full.dev.yml down

# 重启特定服务
docker compose -f docker-compose.full.dev.yml restart chatbot-backend

# 重新构建并启动
docker compose -f docker-compose.full.dev.yml up -d --build

# 仅重新构建特定服务
docker compose -f docker-compose.full.dev.yml build chatbot-backend
docker compose -f docker-compose.full.dev.yml up -d chatbot-backend
```

### 日志查看

```bash
# 查看所有服务日志
docker compose -f docker-compose.full.dev.yml logs -f

# 查看特定服务日志
docker compose -f docker-compose.full.dev.yml logs -f chatbot-backend

# 查看最近 100 行日志
docker compose -f docker-compose.full.dev.yml logs --tail=100 chatbot-backend

# 查看特定时间范围日志
docker compose -f docker-compose.full.dev.yml logs --since 2024-12-23T10:00:00
```

### 容器管理

```bash
# 进入容器 Shell
docker compose -f docker-compose.full.dev.yml exec chatbot-backend bash

# 在容器中执行命令
docker compose -f docker-compose.full.dev.yml exec chatbot-backend python --version

# 查看容器资源使用
docker stats

# 查看容器详细信息
docker inspect chatbot-backend
```

### 数据库管理

```bash
# 连接 MySQL
docker compose -f docker-compose.full.dev.yml exec ars-mysql-db mysql -u root -proot

# 备份数据库
docker compose -f docker-compose.full.dev.yml exec ars-mysql-db mysqldump -u root -proot chatbot > backup_$(date +%Y%m%d).sql

# 恢复数据库
docker compose -f docker-compose.full.dev.yml exec -T ars-mysql-db mysql -u root -proot chatbot < backup_20241223.sql

# 查看数据库列表
docker compose -f docker-compose.full.dev.yml exec ars-mysql-db mysql -u root -proot -e "SHOW DATABASES;"
```

### 数据卷管理

```bash
# 查看数据卷
docker volume ls | grep chatbot

# 查看数据卷详情
docker volume inspect chatbot_qdrant_data

# 备份 Qdrant 数据
docker run --rm -v chatbot_qdrant_data:/data -v $(pwd):/backup alpine tar czf /backup/qdrant_backup_$(date +%Y%m%d).tar.gz -C /data .

# 恢复 Qdrant 数据
docker run --rm -v chatbot_qdrant_data:/data -v $(pwd):/backup alpine tar xzf /backup/qdrant_backup_20241223.tar.gz -C /data
```

## 🐛 故障排查

### 问题 1: MySQL 启动失败

**症状**：
```
ars-mysql-db | [ERROR] [MY-000067] [Server] unknown variable 'default-authentication-plugin=mysql_native_password'
```

**解决方案**：
1. 检查 MySQL 配置文件
2. 确认 MySQL 8.0 兼容性
3. 删除旧数据卷重新初始化：
```bash
docker compose -f docker-compose.full.dev.yml down -v
docker compose -f docker-compose.full.dev.yml up -d
```

### 问题 2: Chatbot Backend 无法连接数据库

**症状**：
```
chatbot-backend | ERROR: Can't connect to MySQL server on 'ars-mysql-db'
```

**解决方案**：
1. 检查 MySQL 健康状态：
```bash
docker compose -f docker-compose.full.dev.yml ps ars-mysql-db
```

2. 确认网络连接：
```bash
docker compose -f docker-compose.full.dev.yml exec chatbot-backend ping ars-mysql-db
```

3. 检查数据库是否创建：
```bash
docker compose -f docker-compose.full.dev.yml exec ars-mysql-db mysql -u root -proot -e "SHOW DATABASES;"
```

### 问题 3: Qdrant 连接失败

**症状**：
```
chatbot-backend | ERROR: Cannot connect to Qdrant at qdrant:6333
```

**解决方案**：
1. 检查 Qdrant 状态：
```bash
docker compose -f docker-compose.full.dev.yml ps chatbot-qdrant
```

2. 访问 Qdrant Dashboard：
```
http://localhost:6333/dashboard
```

3. 检查网络连接：
```bash
docker compose -f docker-compose.full.dev.yml exec chatbot-backend curl http://qdrant:6333/
```

### 问题 4: 前端无法访问后端 API

**症状**：
- 前端显示网络错误
- CORS 错误

**解决方案**：
1. 检查后端 CORS 配置：
```yaml
environment:
  - CORS_ORIGINS=http://localhost:3001
```

2. 确认后端运行正常：
```bash
curl http://localhost:8000/health
```

3. 检查浏览器控制台网络请求

### 问题 5: Ollama 连接超时

**症状**：
```
chatbot-backend | ERROR: Timeout connecting to Ollama at http://192.168.1.101:11434
```

**解决方案**：
1. 确认 Ollama 服务器可访问：
```bash
curl http://192.168.1.101:11434/api/tags
```

2. 增加超时时间：
```yaml
environment:
  - LLM_TEST_TIMEOUT=180  # 增加到 3 分钟
```

3. 检查防火墙设置

4. 使用本地 Ollama（取消注释 docker-compose.yml 中的 ollama 服务）

### 问题 6: 容器内存不足

**症状**：
```
chatbot-backend | Killed
```

**解决方案**：
1. 增加 Docker 内存限制（Docker Desktop 设置）

2. 添加内存限制到 docker-compose.yml：
```yaml
deploy:
  resources:
    limits:
      memory: 2G
    reservations:
      memory: 1G
```

3. 监控内存使用：
```bash
docker stats
```

## 📦 数据备份与恢复

### 完整备份脚本

创建 `backup.sh`:
```bash
#!/bin/bash
BACKUP_DIR="./backups/$(date +%Y%m%d_%H%M%S)"
mkdir -p $BACKUP_DIR

# バックアップ MySQL
docker compose -f docker-compose.full.dev.yml exec -T ars-mysql-db mysqldump -u root -proot --all-databases > $BACKUP_DIR/mysql_all.sql

# バックアップ Qdrant
docker run --rm -v chatbot_qdrant_data:/data -v $(pwd)/$BACKUP_DIR:/backup alpine tar czf /backup/qdrant.tar.gz -C /data .

echo "バックアップ完了: $BACKUP_DIR"
```

### 自动备份（Cron）

```bash
# 添加到 crontab
0 2 * * * /path/to/backup.sh
```
